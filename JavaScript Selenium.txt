It is one of the interfaces in SELENIUM which has below 2 methods.
1. executeScript()
2. executeAsyncScript()

We use JavascriptExecutor when we fail to perform some actions using SELENIUM.

Using sendKeys() method of WEBELEMENT interface, if we try to enter any text in a greyed out
box OR disabled box, we get INVALIDELEMENTSTATEEXCEPTION.
Using executeScript() of JavascriptExecutor interface, we can enter text in a disabled textbox.

Selenium talks to the browser using WebDriver commands, but sometimes an element is **hidden, overlapped, not interactable, or rendered dynamically** in such cases normal `click()` or `sendKeys()` won’t work. In such cases, we inject JavaScript into the browser to do the job directly.

---

## **Where JavaScript is used in Java Selenium**

### 1. **Clicking on hidden or tricky elements**

Sometimes Selenium’s `click()` fails if the element is covered or not in viewport.

```java
JavascriptExecutor js = (JavascriptExecutor) driver;
js.executeScript("arguments[0].click();", element);
```

**Why:** JavaScript clicks directly in the DOM without worrying about visibility issues.

---

### 2. **Scrolling the page**

To scroll until an element is visible:

```java
js.executeScript("arguments[0].scrollIntoView(true);", element);
```

Or to scroll by pixels:

```java
js.executeScript("window.scrollBy(0,500)");
```

**Why:** Helps in dealing with lazy-loaded content and infinite scroll.

---

### 3. **Setting values in input fields**

If `sendKeys()` doesn’t work (e.g., custom JS-based UI), we can set the value directly:

```java
js.executeScript("arguments[0].value='Selenium';", element);
```

**Why:** Directly manipulates DOM elements when WebDriver’s typing is blocked.

---

### 4. **Fetching text or values**

To get the inner text or attributes via DOM:

```java
String text = (String) js.executeScript("return arguments[0].innerText;", element);
```

**Why:** Sometimes `getText()` misses dynamically updated text.

---

### 5. **Highlighting elements (for debugging)**

```java
js.executeScript("arguments[0].style.border='3px solid red'", element);
```

**Why:** Very useful in automation debugging or report screenshots.

---

### 6. **Handling disabled elements**

We can remove the `disabled` attribute to interact with an element:

```java
js.executeScript("arguments[0].removeAttribute('disabled');", element);
```

**Why:** Helps in bypassing UI restrictions (only for testing purposes).

---

### 7. **Navigating via JavaScript**

```java
js.executeScript("window.location = 'https://example.com'");
```

**Why:** Sometimes needed for quick navigation in tests.

---

### 8. **Getting Browser/Window Details**

```java
String title = (String) js.executeScript("return document.title;");
```

**Why:** For fetching DOM or browser data quickly.

If asked *"Where exactly do we use JavaScript in Selenium?"*, the correct short answer is:

> We use `JavascriptExecutor` in Selenium when WebDriver’s native methods fail to interact with elements or when we need browser-level operations like scrolling, clicking hidden elements, setting values, fetching DOM properties, or debugging. It’s mainly for handling tricky UI and advanced automation cases.

Here’s the list of places where JavaScript is used in Java Selenium:

1. Clicking hidden elements
2. Scrolling the page
3. Setting values in input fields
4. Fetching text or values from DOM
5. Highlighting elements (debugging)
6. Handling disabled elements
7. Navigating via JavaScript
8. Getting browser/window details

The only thing that changes is **the JavaScript statement inside `executeScript()`** and whether we **pass `arguments[0]` with an element** or not.
